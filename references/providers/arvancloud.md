| **Machine** | **Cloud Server** (the IaaS product), the smallest general plan: 1 vCPU / 1 GB, image **Ubuntu 24.04**, a **public IPv4** (assigned at creation: **IPv4** at the form's **Network** step; IPv6 can't be chosen yet). Traffic is metered per plan; check the quota, a relay passes everything twice. |
| **Static address** | The provider's reserved address is a **floating IP**. The **public IP** an instance gets at creation stays reserved while the instance is turned off, in either off mode, and is billed while it does; the documentation pages below describe no way to turn it into a floating IP or move it to another instance. So run the phone check on it (`human-steps.md` §6) and keep it; the documented ways to a different address are a new instance (create it before deleting the old one, then check again) or the floating-IP build below. A floating IP connects only to an instance **without** a public IP, on a private network that has a gateway — a different build from the **Instance** click path below. Cost: the address is billed as its own line, also while the instance is off; the documentation gives no figure — check the provider's price page. |
| **Signup** | Email and a **local mobile number** for confirmation; **identity verification** (national ID) is required to activate billing on the local site. There is no separate international signup at last check — tell the person up front. |
| **Payment** | Local cards in local currency; some resellers take crypto. Prepaid balance model: top up, then spend. |
| **Known blocked ranges** | The domestic ranges are the likeliest to be reachable on carrier-restricted networks in that country — that is the point of a relay there — but likely is not certain: one address gets through where another does not, so run the phone check before the install (`human-steps.md` §6). The foreign data centers belong to a provider that answers to that country's law: as an exit they are reachable but not independent, say so in one sentence (same note as for other home-registered hosts in `provisioning.md`). |
| **Firewall** | **Firewall groups** (the panel's **Firewall** section). A new instance gets the default firewall settings: it joins the **Default** group unless it is put in another group at creation. The provider's documentation (read 2026-10-05, sources under the click paths) says a group starts with rules that block all inbound traffic and allow all outbound, with `22` (SSH), `3389` (Remote Desktop) and ICMP open. The layer needs, inbound from any address: relay `22` tcp and `443/51821` udp; exit `22/80/443` tcp plus `443/51821` udp in the `single` profile. Of these, the defaults open only `22`: add an inbound rule for each of the others (**Add New Rule** → **ingress**, type **Optional**, the protocol, the port → **Save**). A group's rules apply to every instance in it: if the person has other instances, put this one in a group of its own (**Create New Group** before creating the instance, then pick it at the form's **Firewall** step) and add the rules there. |
| **Quirks** | The panel and documentation are in the local language first; the English switch is at the top of the page. The create-instance form has a user-data field: under **Advance Settings → More Options**, an initial script, a User Data script that runs automatically, only once, while the instance is created (the provider's English documentation, read 2026-10-04, source under the click paths). Use it for the exit installer only, never the relay's. Not verified here: whether images ship with a pre-enabled firewall (`ufw`) — run the checks in `providers/generic-ubuntu.md` before installing. Plans are prepaid: a relay with an exhausted balance stops without warning — put the top-up date in the handout. |

## Click paths

**Account** — the provider's site → **Sign up** → mobile number → confirmation code → complete identity verification → **Wallet** → top up.

**Instance** — **Cloud Server** → **New Instance** → Data center (domestic for a relay) → Image **Ubuntu 24.04** → the smallest plan (**Continue** after each of these three) → **Advance Settings** → **Accessibility Type**: **SSH Key**, with the public key from `~/.ssh/vpn-kit.pub` (or the person's own; a key the panel doesn't list yet is added under **SSH Key → New SSH Key**: paste it, name it, save) → **Network**: **IPv4** (IPv6 can't be chosen yet) → **Firewall**: the default settings, or the instance's own group if one was made (either way, the group needs the inbound rules above) → **Continue** → **Final Review**: name `vpn-relay` (or `vpn-exit`) → **Continue**. A window then shows the login details, once (they are also emailed). The IP is on the instance page.

*Instance and firewall sources (the provider's English documentation, read 2026-10-05; the pages carry no date): [instances, creating one](https://docs.arvancloud.ir/en/cloud-server/instance/#create-an-instance) (**New Instance**, **Continue**, **Accessibility Type**, the IP version, the default firewall settings, **Final Review**), [connecting, SSH keys](https://docs.arvancloud.ir/en/cloud-server/instance/connection/#how-to-create-private-and-public-key) (**New SSH Key**), [firewall](https://docs.arvancloud.ir/en/cloud-server/firewall/) (the **Default** group, a new group's default rules, **Add New Rule**).*

**Static address (§6)** — by default, nothing to click: the instance's public IP stays reserved while the instance is turned off, in either off mode; check it (§6) and keep it. A floating IP instead (instance on a private network with a gateway, no public IP): **Cloud Server → Networks → Float IP → Assign Floating IP** → a description, optional → **Assign IP**. The documentation gives the connect step for the CLI only: `arvan iaas network float-ip create "vpn-relay" --az <data center>`, then `arvan iaas network float-ip connect <server-id> --port <port-id> --float-ip <floating-ip-id>`. A floating IP you do not keep: `arvan iaas network float-ip disconnect <floating-ip-id>`, then `arvan iaas network float-ip delete <floating-ip-id>`.

*Static-address sources (the provider's documentation, read 2026-09-29): [network, floating IP](https://docs.arvancloud.ir/en/cloud-server/network/), [instances, turning off](https://docs.arvancloud.ir/en/cloud-server/instance/), [CLI network commands](https://docs.arvancloud.ir/fa/developer-tools/cli/cloud-server/network/) (local language only), [floating IP resource](https://docs.arvancloud.ir/fa/dev/references/terraform/cloud-server/resources/iaas_floating_ip/).*

*User-data source (the provider's documentation, read 2026-10-04; the page carries no date): [instances, creating one, "More Options"](https://docs.arvancloud.ir/en/cloud-server/instance/#more-options).*

**Then** — relay: rebuild the installers once `exit_ip` and `ntfy_alert_token` are in `params.json`, `setup-relay.sh` over SSH, `vpn-verify.sh`, `relay_ip` into `params.json`. Exit: DNS records, `dns-check`, `setup-exit.sh` over SSH as root.
