| **Static address** | The provider's reserved address is a **floating IP**. So run the phone check on it (`human-steps.md` §6) and keep it; the documented ways to a different address are a new instance (create it before deleting the old one, then check again) or the floating-IP build below. A floating IP connects only to an instance **without** a public IP, on a private network that has a gateway — a different build from the **Instance** click path below. Cost: the address is billed as its own line, also while the instance is off; the documentation gives no figure — check the provider's price page. |

## Click paths

**Account** — the provider's site → **Sign up** → mobile number → confirmation code → complete identity verification → **Wallet** → top up.

**Instance** — **Cloud Server → Create** → Data center (domestic for a relay) → Image **Ubuntu 24.04** → the smallest plan → **Public IP: on** → **SSH key**: paste the public key from `~/.ssh/vpn-kit.pub` (or the person's own) → **Security group**: add the inbound rules above → Name `vpn-relay` (or `vpn-exit`) → **Create**. The IP is on the instance page.

**Static address (§6)** — by default, nothing to click: the instance's public IP stays reserved while the instance is turned off, in either off mode; check it (§6) and keep it. A floating IP instead (instance on a private network with a gateway, no public IP): **Cloud Server → Networks → Float IP → Assign Floating IP** → a description, optional → **Assign IP**. The documentation gives the connect step for the CLI only: `arvan iaas network float-ip create "vpn-relay" --az <data center>`, then `arvan iaas network float-ip connect <server-id> --port <port-id> --float-ip <floating-ip-id>`. A floating IP you do not keep: `arvan iaas network float-ip disconnect <floating-ip-id>`, then `arvan iaas network float-ip delete <floating-ip-id>`.
