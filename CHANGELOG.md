- ci(repo): `.github/wording-guard.sh` matches the Cyrillic terms as stems, so every case form fails, not only the dictionary form (#39). The site repo's guard gets the same patterns.
- fix(installer): the line `vpn-drill.sh` writes to its log when it lifts the simulated outage now says "restored" (#39); the old word matched the new wording guard. One string in a file the installer puts on the server; no logic change.
- docs(skill): the README and `SKILL.md` say what the default layout really uses (#38). On the one-server (`single`) layout devices connect with plain WireGuard, straight to the server abroad; VLESS + XHTTP + REALITY carries the relay → exit link of the `relay` profile and the `vless://` link for VLESS-app users (Hiddify, v2rayNG). The README's "What you get" bullet and its "Why REALITY" section now say so, and add that some networks detect or slow down plain WireGuard, where the `relay` profile or a VLESS app is the better choice. The REALITY private key is no longer said to exist "only on the exit": it is in `params.json` on the machine where the skill runs, inside `out/setup-exit.sh` and, when the server is created through cloud-init, in its metadata; the rule that stays is that it goes into no chat, no project and no relay installer (README "Hard rules", `SKILL.md` iron rule 5). "The keys never leave your machine" became: made on your machine, installed on your server, and the first device's code passes through the chat and can be replaced from the panel. "Works in both directions" now carries its limit: reaching home needs the server in the home country, and the automated path creates servers only in DigitalOcean's regions. The unmeasured "in fifteen minutes" is gone from the README's `relay` paragraph. `references/architecture.md` no longer says that on the one-server layout REALITY is for phones inside the filtered country: WireGuard is what every device gets by default. Nothing on any server changed.

The intro no longer says "a free Claude skill": it says what the skill is (plain instructions plus standard-library Python and bash scripts that an agent follows), that the agent creates the server on DigitalOcean and installs everything, and that only Claude Code has been tested; other agents that load the open Agent Skills format haven't been. The requirements table's column is "What the agent does", each row carries its status (Claude Code tested; claude.ai untested until #4; Cowork untested) and a new row covers other agents with a shell and network (Codex CLI, Gemini CLI, Cursor; untested). The quick start gains "Other agents (untested)": `git clone` into the agent's skills folder (`~/.agents/skills/homeport` for Codex CLI) and an invitation to open an issue and say how it went. "Claude" stays only where a statement is true only of Claude: the tested row, the plugin install and update, claude.ai and the "Upgrading from Burrow" note; everywhere else the README says "your agent" (the free path) or "Homeport's agent" (the paid one), a naming rule `CONTRIBUTING.md` now carries under "Wording rules". The paid path opens in January 2027, not November. Nothing on any server changed.

## 0.6.0 — 2026-09-27

- fix(skill): the skill no longer promises a fixed server price (#34). At the cost step the agent says the monthly price the host lists that day, "before tax", and the domain at the price the registrar shows at checkout. For DigitalOcean the number comes from the new `provision-do.py price --size s-1vcpu-1gb`, which reads `GET /v2/sizes` (following pagination) and prints the listed `price_monthly`; the API needs a token, so before the key exists the person reads the price off DigitalOcean's pricing page, and `price` confirms it right after the key check, before anything is created. Other hosts, and the relay's host: the person reads the price off the host's page and the agent repeats it. Without `DO_TOKEN`, `price` exits non-zero with a plain message; the existing subcommands are unchanged. `make-handout.py --price-exit` is now required (it defaulted to "$6"): the handout carries the price quoted at setup; the English template's `{price_exit}` has no default either, and its domain line no longer names a price. The README intro carries no price and the budget line is dated (DigitalOcean's listed price on 27 Sep 2026, before tax); droplets are named by size (`s-1vcpu-1gb`, "the next size up (2 TB)") in `SKILL.md`, `architecture.md` and `operations.md`. The Russian `lang/ru.md` and `handout-ru.md` changed only where they hard-coded a server price (and the totals built on it). `references/providers/*.md` keep their dated prices.
- fix(repo): `.github/wording-guard.sh` no longer fails in a git worktree, where `.git` is a file (`gitdir: …`) and its path can contain the old name (#45). The legend's own display rule beat the hide rule; the hide rule for one-server-only elements now wins everywhere, as the two-server one already did. The one-server panel is unchanged. Changes `dashboard.html`, a file the installer puts on the server (CSS only).

## 0.3.0 — 2026-09-25

- docs(skill): global positioning — every country-specific term removed from the public surface (skill, references, README, landing strings, script comments and printed strings); the `relay` profile is described only as "your network restricts direct foreign connections or only allows listed IP ranges", with a home-country relay at any Ubuntu 24.04 provider. `references/providers/` gets Alibaba Cloud and ArvanCloud, and every provider file the same rows: signup requirements, machine/region/image, firewall, quirks, last-verified date; a neutral warning about home-country providers at the top of the relay section. Default split-tunnel list (`direct-domains.txt`) ships empty — fill it per household from the panel (`home_geoip` still routes home-country addresses directly). `CONTRIBUTING.md` "Wording rules" + `.github/wording-guard.sh` in CI. Printed strings in `make-handout.py` and the panel hint changed accordingly; no script logic changed.

- `fix(installer)` — **iPhones get push notifications again.** `/etc/ntfy/server.yml` now
  carries `upstream-base-url: "https://ntfy.sh"`: iOS keeps no background connection to a
  self-hosted ntfy, so only ntfy.sh can wake the phone. Just the bare fact that a message
  exists goes upstream — no text, no topic; the phone fetches the text from your own
  server. A server built before this release needs the line added by hand plus
  `systemctl restart ntfy`, and the subscription in the app deleted and re-created —
  otherwise the phone never re-registers (`references/troubleshooting.md`).
- `fix(installer)` — **a drill no longer takes the operator down with it.**
  `vpn-drill.sh` postpones itself while people are using the channel (more than 5 MB in
  the last five minutes, from `stats.db`, or a WireGuard handshake in the last 180 s when
  that database is missing): it notifies, logs `skip: clients active` and exits 3 without
  touching the route. A plain run now detaches into the transient unit
  `vpn-drill-manual` and returns at once, so an SSH session dying with the channel can no
  longer kill the run and leave the block standing. New flags `--force` (run anyway) and
  `--fg` (run in this process); unknown flags exit 2; running under systemd implies
  `--fg`, so `vpn-drill.service` and `vpn-drill-check.service` are unchanged, and
  `--check` still exits before any of this and breaks nothing.
- `docs(skill)` — the first device is now checked **on mobile data, Wi-Fi off**, before
  any QR codes go out; if Wi-Fi works and mobile data does not, `alt_port` 443 first and
  only then a different provider in the users' country — the relay's IP is written into
  every config the panel issues, so moving the relay afterwards means re-issuing every
  device (`SKILL.md` step 7, `lang/en.md`, `lang/ru.md`, `references/human-steps.md`).
- `docs(skill)` — `references/architecture.md` gains "A standby exit instead of the direct
  fallback": why the direct fallback is weakest on carrier-restricted networks, the shape
  of an exit B, the files it would touch, and why it is not built until paying users
  confirm the direct fallback is useless for them.
